# Migrating to Tint 0.2

Tint 0.2 is an intentional API reset. It moves application-facing state behind one root client while keeping visual components controlled and provider-free.

## Installation and client root

Pin Tint to a reviewed Git commit or submodule revision. Tint remains private and ships raw TypeScript.

```json
{
  "dependencies": {
    "tint": "github:MylesLandais/tint#<commit-sha>"
  }
}
```

Create one client and mount its provider once:

```tsx
import { createTintClient, TintClientProvider } from '@nebula/tint/client'

const client = createTintClient({ request, auth, navigation, realtime, uploads, storage })

root.render(<TintClientProvider client={client}><App /></TintClientProvider>)
```

Only adapter hooks require the provider. `Avatar`, `Surface`, `AppShell`, charts, media components, and `WorkspaceGrid` continue to work from controlled props alone.

## Breaking import changes

| 0.1 | 0.2 |
| --- | --- |
| `@nebula/tint/auth-client` | Auth client exports from `@nebula/tint/auth` |
| `@nebula/tint/calendar-client` | CalDAV exports from `@nebula/tint/calendar` |
| `AuthProvider` | `TintClientProvider` from `@nebula/tint/client` |
| `useAuth`, `useSession` from `@nebula/tint/auth` | Hooks from `@nebula/tint/client` |
| `SignInForm` | `IdentifierSignInForm` |
| `createAuthFormSchema` | `createCredentialFormSchema` |
| `deriveNotifications` | Feed-only `deriveFeedNotifications`; generic rows use `Notification` directly |

Password operations now take `{ identifier, password }`, and `AuthConfig` declares `identifierKind`. `AuthUser` uses the shared `Identity` shape (`name`, `avatarUrl`, `presence`) and no longer requires an email.

Application-specific credential workflows use typed operations:

```ts
const recover = defineAuthOperation<{ username: string }, { challengeId: string }>('recover')
const result = await auth.execute(recover, { username })
```

Secrets returned by custom operations are not copied into auth snapshots or cross-tab events.

## New capability packages

- `@nebula/tint/identity`, `@nebula/tint/surface`, and `@nebula/tint/status`
- `@nebula/tint/navigation` and `@nebula/tint/menu`
- `@nebula/tint/media-assets`
- `@nebula/tint/charts`
- `@nebula/tint/workspace-grid`

Base UI, Recharts, and React Grid Layout are private implementation details. Do not import their types to configure Tint components. Continue importing `@nebula/tint/styles.css` once; it now includes the workspace grid styling as well.

## Application-owned behavior

Tint does not absorb route definitions, endpoints, credentials, retry policies, encryption, persistence implementations, moderation rules, social semantics, recovery-key cryptography, or backend behavior. Supply those through adapters and controlled props.
